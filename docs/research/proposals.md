# 提案（役割①の出力）

毎時、役割①が書き手の体験・人が集まり残るか（集客/定着）の観点で 1 件書く。
新しいものを上に。役割②はここの最新を読んで設計する。
標準制約（決済を持たない・依存を増やさない・数字を競争にしない・
個人単位の行動計測をしない・検査/認証/上限を緩めない・第三者 JS を使わない）に
触れる提案は **要判断** と明記し、人が決めるまで役割②以降に流さない。

書式:

## <日時> <提案名>
- 状態: 未設計 / 設計済み / 実装済み / 要判断
- 何を: / なぜ: / 期待効果: / 根拠の事例: case-studies.md の番号

- 状態: 未設計 → ②へ
- 観点: **集客/定着**（要判断ではない）

### どうやって分かったか

**A を実装したついでに出た。**③が server モードで 3 経路を引いて、
壊れていないことを確かめたときに見えた。

```
/         og:url ある（この周で足した）
/stories/ og:url ある
/tags/    og:url **無い**
```

**①の 09:40 の測定は 4 経路だったが、`/tags/` を見ていなかった。**
分母の外にあったものが、実装の確認で出てきた。

### もう 1 つ、同じページに

`/tags/` の `og:title` は **`タグから探す | CreatorYard`** で、
**サイト名が入っている。**他のページは入っていない
（`Creator Story` / `初めての投稿` / `sidra_studio の記録`）。

事例 36 に出典がある —— Meta は「**サイト名などのブランドを付けない記事の
題名**」と言っていて、`designs.md` 2026-08-09 の表にも

**ブランドは `og:site_name` が運ぶ**（そちらは正しく入っている）。

**原因の見当はついているが、②が実物で確かめること** ——
`/tags/` は `metadata` に `title` を書いていて、layout の
`title.template`（`%s | CreatorYard`）が当たっている可能性がある。
**当たっているなら、`og:title` だけ template を通さない形にする。**

### なぜ小さくても取るか

**貼られるのはトップと Story だけではない。**「Godot のつまずきならここ」と
`/tags/` を貼る人がいる。**そのとき出るカードだけ、他と作りが違う。**

U-5（0 件の面の作り方が揃っていない）・U-6（同じ語の扱いが 2 通り）と

## 2026-08-19 09:40 **共有カードを測った —— 足りないのは 2 つ。片方は要判断、片方は取れる**

- 状態: **A（`og:url`）= 未設計 → ②へ／B（`og:image`）= 要判断（社長へ）。②以降に流さない**
- 観点: **集客/定着**

### なぜここを測ったか

**サイトは全ページ `noindex, nofollow`。**検索からは 1 人も来ない。
つまり**いま人が入ってくる道は「誰かが貼ったリンク」だけ**で、
**共有カードが集客の面のすべて**である。

### 測った（本番・4 経路）

| 項目 | `/` | `/stories/` | `/story/<id>/` | `/creators/<h>/` |
| --- | --- | --- | --- | --- |
| `og:title` | ある | ある | ある | ある |
| `og:description` | ある | ある | ある | ある |
| `og:site_name` | ある | ある | ある | ある |
| `og:type` | ある | ある | ある | ある |
| **`og:url`** | **無い** | ある | ある | ある |
| **`og:image`** | **無い** | **無い** | **無い** | **無い** |
| `twitter:card` | `summary` | `summary` | `summary` | `summary` |

**測り直しを 1 回している。**最初の型が `og:[a-z:]+` で、**下線を含む
`og:site_name` を落としていた。**そのまま書けば「site_name が無い」という
誤った報告になっていた。**型で数えたら、型のほうを疑う。**

### A —— **トップだけ `og:url` が無い**（要判断ではない）

事例 36 のとおり、**`og:url` は OGP の必須 4 項目の 1 つ**である。
無いと、`?utm_source=…` などが付いたリンクが**別の対象として扱われる**。

**いちばん多く貼られるのはトップである。**そこだけ抜けている。

**原因は実物で確かめた。**`app/page.common.tsx` に `metadata` が無く、
`app/layout.common.tsx` の `alternatesFor(null)`（canonical なし）を
そのまま受けている。他のページは `generateMetadata` で canonical を作って
`openGraph.url` に入れている。**トップにも同じ形を置けば済む。**

**②への注意**: `openGraph` を子で書くと**親の入れ子がまとめて置き換わる**
（`SITE_OG` の展開を忘れると `og:site_name` と `og:locale` が消える。
この repo で 2 回踏んでいる罠）。**焼いた HTML を引いて確かめること。**

### B —— **`og:image` は要判断。ここでは流さない**

**過去に決めてある。**`designs.md` 2026-08-09 22:33:

> `og:image` | **出さない** | 画像は未定（提案 25 は要判断）。
> **無いものを指す URL や空文字を焼くほうが悪い**

**①はこれを覆さない。**ただし**決めた理由のほうは、もう成り立っていない**
ので、事実だけ社長へ渡す:

| 当時 | いま |
| --- | --- |
| **画像が無い** | `public/media/hero-poster.jpg` が**在る**。権利確認済み（CREDITS.md・RIGHTS_APPROVED）で、**既に公開配信もしている** |
| 書き手の画像も無い | U-1 で**カードに画像を出す**ようになった。`story.image` を持つ Story は自前の絵を持つ |

**つまり「画像が無いから出さない」は、いま当てはまらない。**
**それでも①は実装しない** —— 「OGP 画像を作るか」は**社長の判断事項**として
`mediation.md` に残っているままだからである（要判断の項目は、理由が変わっても
**人が決め直すまで動かさない**）。

**社長へ渡すのは選択肢だけ**（決めるのは社長）:

1. **何もしない**（いまのまま。カードは文字だけ）
2. **サイト共通の 1 枚に `hero-poster.jpg` を使う**（新しい素材を作らない・
   権利確認は済んでいる）
3. **Story が自分の画像を持つときだけ、それを使う**（書き手の絵が出る。
   ただし**差し替えても URL が同じなら古い絵が残る** —— 事例 36 の
   「`og:image` は URL でキャッシュされる」。O-4 と同じ手当てが要る）

**①の見立ては 2 →（あとで）3 だが、決めるのは社長である。**

### 根拠の事例

case-studies.md **36**（Open Graph 公式＋Meta 公式。`og:url` は必須 4 項目・
`og:image` は URL でキャッシュされる）

**書き終えた直後の人に「書き始める」と言っている。**

**書き手の側に、確かめる手段が無い。**答えが残ることを知っているのは

**利用者がいま知りたい 1 つのこと**だけを言えばよい ——
**「いま答えた 4 つは残っている」。**

**続きへ戻る**のが実際に起きること）。**ただし文言は②が決める。**
①は「ずれている」までを言う。

- **4 問書いた人が、そこで閉じない**。いま閉じる理由は「消えるかもしれない」

  しない決まりなので、**この提案は「離脱率が高い」を根拠にしていない。**

- 手元の server モードで測った。**本番では未確認**（本番は 16 本うしろで、

**問題は表示だけである。**

### 何を確かめたか

gdp が 18:00 に **B 案**（タグ件数を出さない・件数順を廃止・**タグ名の安定した昇順**）を
決め、検証指標に **「Story件数変更前後のタグ表示順差分: 0件」** を置いた。

**素直に `Intl.Collator('ja')` で並べると、この指標を満たせない。**

```
> new Intl.Collator('ja').compare('あ','ア')
0                                     ← ひらがなとカタカナが「同値」

> ['あ','ア'].sort(c.compare).join(',')
あ,ア
> ['ア','あ'].sort(c.compare).join(',')
ア,あ                                  ← 入力順で結果が変わる
```

**比較器が 0 を返す 2 つは、`Array.sort` が入力順のまま残す**（ES2019 以降 sort は
安定なので、同値は元の順序を保つ）。そして `tagIndex()` の入力順は
**`#readAll()` が返す Story の順**、つまり**どの Story が存在するかで変わる。**

→ **Story が 1 本増減しただけで、`あ` と `ア` の表示順が入れ替わりうる。**
gdp の「件数変更前後の表示順差分 0 件」に**そのまま反する。**

### ほかに確かめたこと

| 見たもの | 結果 |
| --- | --- |
| `ja` locale は使えるか | **使える**（`Intl.Collator.supportedLocalesOf(['ja'])` が空でない） |
| `localeCompare()` 既定 と `'ja'` 指定 | この環境では**同じ並び**。ただし**環境依存なので `'ja'` を明示するべき** |
| `ケ` vs `ヶ` | `1`（別物として扱われる。ここは問題なし） |
| `3d` vs `３Ｄ` | `-1`。ただし `normalizeTag` が NFKC ＋ ASCII 小文字化するので、**そもそも同じタグに畳まれる**（衝突しない） |

### 提案する直し方（1 行）

比較器に**決定的な同値解決**を足す。

```js
const collator = new Intl.Collator('ja')
const byName = (a, b) => collator.compare(a, b) || (a < b ? -1 : a > b ? 1 : 0)
```

`||` の右側は**コードポイント順**で、同じ 2 語なら必ず同じ答えを返す。
これで**入力順に依存しなくなる**。
