# 提案（役割①の出力）

毎時、役割①が書き手の体験・人が集まり残るか（集客/定着）の観点で 1 件書く。
新しいものを上に。役割②はここの最新を読んで設計する。
標準制約（決済を持たない・依存を増やさない・数字を競争にしない・
個人単位の行動計測をしない・検査/認証/上限を緩めない・第三者 JS を使わない）に
触れる提案は **要判断** と明記し、人が決めるまで役割②以降に流さない。

書式:

## <日時> <提案名>
- 状態: 未設計 / 設計済み / 実装済み / 要判断
- 何を: / なぜ: / 期待効果: / 根拠の事例: case-studies.md の番号

---

## 2026-08-10 04:18 JST 再ビルドの間隔は「soft 404 の窓」で決める（段階 B への申し送り・A-5 では作らない）

- 状態: **設計済み**（designs 2026-08-10 04:33 の A-5 に理由として入れた。**実装は段階 B で、社長の実行判断が要る**）
- 根拠の事例: case-studies.md の **40**

**何を:**

1. **A-5 では何も作らない。**`try_files` の差し替えは設計どおり進める
2. **段階 B の再ビルド設計に、間隔を決める理由として
   「soft 404 の窓」を足す。**「なんとなく日 1 回」ではなく
   「**書いてから焼かれるまでの時間 ＝ 検索に error page と見られる時間**」
   として決める
3. **④の監査項目に 1 つ足す**（本番が立ったら）:
   **存在しない id を叩いて、何が返るか**を実際に見る

**なぜ:**

- 事例 40 のとおり、A-5 のフォールバックは**存在しない id にも 200 で
  シェルを返し、中身は「見つかりません」**になる。Google の定義では
  これが **soft 404**
- **これは直せる欠陥ではない。**nginx はファイルの有無しか見ないので、
  「まだ焼かれていない新しい Story」と「存在しない id」を区別できない。
  区別するには nginx から API に問い合わせることになり、
  **静的配信にした意味が消える**
- **シェルに `noindex` を付ける手は採れない。**シェルは焼かれる前の
  新しい Story を出すためのものでもあるので、常に `noindex` にすると
  **書いたばかりの記録が検索に出なくなる**。書き手の体験として最悪
- 残る手は**窓を短くすること 1 つ**。だから再ビルドの間隔は
  「重いから日 1 回」ではなく「**窓をどこまで許すか**」で決める

**期待効果（観点別）:**

| 観点 | 見立て |
| --- | --- |
| 書き手の体験 | **ここが本命。**「公開したのに検索に出ない」時間が短くなる。書いた直後にリンクを貼る人にとっては、貼った先の見え方に直結する |
| 集客・定着 | タグ SEO は集客の優先順位に入っている（HANDOVER §3）。窓が長いほど、新しい記録が拾われにくい |
| セキュリティ | **増えない。**むしろ nginx から API に問い合わせる案を採らないことで、静的配信の面が広がらずに済む |

**被害の見積もり（過大に言わない）:** A-4 でシェル 3 枚を sitemap から
外したので、Google が自発的に踏むのは**誰かがリンクした URL だけ**。
撤退条件の規模（30 本）では、**急いで対処するほどの話ではない**。
**段階 B の設計に理由として残せば足りる。**

**要判断ではない**が、**段階 B の実行そのものは社長の判断**（VPS・
証明書・再ビルドの体制）なので、②はここまでを設計に書いて止める。

## 2026-08-10 02:14 JST sitemap は**書かないものを決めてから**書く（A-4 に入れる）

- 状態: **設計済み**（designs 2026-08-10 02:33 の A-4。要判断ではない）
- 根拠の事例: case-studies.md の **39**（＋ 38）

**何を（3 つとも「書かない」の話）:**

1. **`priority` と `changefreq` を出さない。**Google が「無視する」と
   明言している（事例 39）
2. **`SITE_ORIGIN` が無いときは sitemap を空にする。**相対 URL を
   書いて埋めない
3. `lastmod` は既存の決めのまま（`updatedAt`・ビルド時刻を使わない・
   固定ページには出さない）。**変更なし**。事例 39 の記述と一致している
   ことを確かめただけ

**なぜ:**

- **1 について。**Next の `sitemap.ts` は `priority` と
  `changeFrequency` を受け取れるので、**埋めたくなる**。しかし
  読まれないものを埋めると「手入れした」ように見えて実態が無い。
  しかも `priority: 0.8` のような数字には**根拠が無い**。
  このプロジェクトは「確かめられない数字を並べない」を決まりにしている
- **2 について。**Google は「**fully-qualified, absolute URLs**」を
  求め、「**exactly as listed**（書いたとおりに辿る）」と書いている。
  `SITE_ORIGIN` が無ければ絶対 URL は作れない。ここで相対 URL を
  書くと、**辿れない URL の一覧を出す**ことになる。
  **空の sitemap のほうが正直で、害が無い**
  （`og:url` を出さない決めと同じ考え方。A-2 から一貫させる）
- **3 について。**「consistently and verifiably accurate なときだけ
  使う」とあるので、**ビルド時刻を入れると逆効果**。毎回全ページが
  更新されたことになり、当てにならない印が付く

**期待効果（観点別）:**

| 観点 | 見立て |
| --- | --- |
| 書き手の体験 | 直接は効かない |
| 集客・定着 | **無いものを足すのではなく、嘘を減らす**。`lastmod` が信用されれば、直した記録が拾われやすくなる |
| セキュリティ | **増えない。**むしろ「`SITE_ORIGIN` 未設定のまま本番に出た」場合に、間違った URL の一覧を配らずに済む |

**②への申し送り:** ⑤ 01:38 の指示（**受け皿 `_none` を載せない**）と
あわせて、A-4 の設計は「**載せないもの**」の一覧から書き始めると
抜けにくい。載せないものは現時点で 3 つ ——
`_none` の 2 ページ / `priority`・`changefreq` / 固定ページの `lastmod`。

**上限の記録（今は何もしない）:** 1 つの sitemap は
**50,000 URL・50MB** まで。CreatorYard の URL 数は
「Story ＋ ハンドル ＋ タグ ＋ 固定ページ」なので、
**分割が要るのはずっと先**。**いま分割の仕組みを作らない**
（撤退条件の規模は 30 本）。数字だけ残す。

## 2026-08-10 00:22 JST 焼くページに `rel="canonical"` を入れる（A-3 と同じ回で）

- 状態: **設計済み**（designs 2026-08-10 00:34 の A-3 に含めた。要判断ではない）
- 根拠の事例: case-studies.md の **38**

**何を:**

1. `app/s/[id]/`・`app/w/[handle]/`・`app/tags/[tag]/` の
   `generateMetadata` に `rel="canonical"` を足す。値は **`og:url` と同じ**
   （Next の metadata では `alternates.canonical`。**③が焼いた HTML で
   実物を確かめる**）
2. `SITE_ORIGIN` が無ければ**出さない**。`og:url` と同じ決めにそろえる
3. **リダイレクトは今回やらない。**段階 B の nginx の論点として残す

**なぜ:**

- 事例 38 のとおり、**タグページは同じ中身に複数の URL が付く**。
  `/tags/Godot/` と `/tags/godot/` と `/tags/godot`（末尾スラッシュ無し）が
  すべて同じ Story を返す。焼かれるのは正規化した 1 本だけで、
  ゆれた URL は try_files でシェルに落ち、**同じ中身を別の URL で出す**
- Google の並びでは **`rel="canonical"` は「強い信号」、sitemap は
  「弱い信号」**。A-4 で sitemap に正規 URL を並べるだけでは足りない
- 一番強いのはリダイレクトだが、それは nginx の仕事で**段階 B**。
  **`rel="canonical"` は焼く側で今すぐ入れられる**ので、順番として先
- **必須ではない**（Google 自身が「none of them are required」と書いている）。
  だから**大げさな仕組みは作らない。**1 行足すだけに留める

**期待効果（観点別）:**

| 観点 | 見立て |
| --- | --- |
| 書き手の体験 | 直接は効かない。ただし**自分のページを貼ったときに、検索結果に出る URL が 1 本に定まる**のは地味に効く |
| 集客・定着 | タグ SEO は集客の優先順位に入っている（HANDOVER §3）。同じ中身が複数の URL に散ると、その分が薄まる |
| セキュリティ | **増えない。**出すのは自分のサイトの URL 1 本だけ |

**②への注意:** `og:url` と canonical は**同じ値を 2 か所に書くことになる**。
`lib/og.ts` の `absoluteUrl` を両方から呼ぶ形にして、**ずれないようにする**。
ずれると「og が指す URL と canonical が違う」という一番よくない状態になる。

## 2026-08-09 22:22 JST `og:image` は**サイト共通の 1 枚**を静的に置く（Story ごとに作らない）

- 状態: **一部 要判断**（画像そのものの制作＝ブランドの見た目は社長の判断）
- 根拠の事例: case-studies.md の **36**（＋ 35）

**何を:**

1. `public/ogp-1.png`（仮名）を **1 枚だけ**置き、**全ページ共通**で
   `og:image` に指定する。Story ごとに違う画像は**作らない**
2. ファイル名に**版番号を入れる**（`ogp-1.png` → 差し替え時は `ogp-2.png`）
3. `og:description` は**文の切れ目で切る**。「n 文字で切る」にしない
4. `og:url` は `https://creatoryard.io/s/<id>/` の**末尾スラッシュ有りに統一**

**なぜ:**

- 事例 36 のとおり、**`og:image` は Open Graph 仕様の必須 4 項目の 1 つ**。
  ②の A-2 設計（20:20）は `og:title` / `og:description` / `og:url` /
  `og:type` の 4 つで、**`og:image` が抜けている**
- **Story ごとの画像生成は 3 つの理由で採らない:**
  - `output: 'export'` では**動的な画像生成そのものができない**
    （事例 35 で metadata が Server Component 専用と分かったのと同じ層の話）
  - **利用者が書いた文字列をそのまま画像に焼く経路になる。**
    検査していない入力が画像として外に出る面を、わざわざ作ることになる
  - 依存が要る（画像生成の道具）。**依存を増やさない決まりに触れる**
- **静的な 1 枚なら攻撃面が増えない。**置くのはただのファイルで、
  第三者 JS でも計測でもない
- 事例 36 の「**画像は URL でキャッシュされ、URL が変わらない限り
  更新されない**」から、版番号を名前に入れておく。入れないと、
  差し替えたのに古い画像が出続ける事故を後で踏む
- `og:description` の長さは**出典が割れている**（仕様は 1〜2 文、Meta は
  2〜4 文）。**割れているものに数字で決め打ちしない。**文の切れ目で切れば
  どちらの範囲にも収まり、途中で切れた文が外に出ない

**期待効果（観点別）:**

| 観点 | 見立て |
| --- | --- |
| 書き手の体験 | 自分の記録を貼ったときに**まともなカードで出る**。CreatorYard は「書いたものを本人が持ち出す」ことを推している（GAMEYARD リンク・RSS）ので、貼ったときの見た目は書き手の体験そのもの |
| 集客・定着 | OGP は流入に効く部分。ただし**画像に数字を焼かない**（「〇〇日目」などのカウンタは、数字を競争にしない決まりに触れる） |
| セキュリティ | **増えない。**静的ファイル 1 枚。動的生成を採らないことで、未検査の入力が外に出る経路を作らずに済む |

**要判断（社長へ）:** 画像そのもの（何を描くか・ロゴの扱い）は
**ブランドの見た目**なので、AI が勝手に作りません。
**「1 枚置く」という方針までを②へ流し、画像が用意されるまでは
`og:image` を出さない**（無いものを指す URL を焼くほうが悪い）形でよいか。
急ぎではありません — A-2 は `og:image` 抜きで先に通せます。
